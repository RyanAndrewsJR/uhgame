# DECISIONS.md: Design Decisions Log

**Read when:** before proposing changes to an existing design, or when asked why something works the way it does.
**Depends on:** nothing. **Used by:** every doc.

## How to use
- One row per decision: date (YYYY-MM-DD), the decision, and why.
- Add new decisions to the matching system section (add a section if none fits). If a decision changes how a system works, also update that system's doc.
- Never delete a row. When a decision is reversed, strike it through (`~~text~~`), add "superseded YYYY-MM-DD, see below", and add the new decision as its own row.
- Don't re-suggest anything that is rejected or superseded here unless Ryan reopens it.

## Audio
| Date | Decision | Why |
|---|---|---|
| 2026-09-27 | Names: `Audio` (autoload), `SoundEvent` (one sound's data), `AudioMix` (the mix-wide numbers, like HitFeel), `CombatSounds` (the Events listener, a child of Audio). Loop handles are plain `int`s (0 = nothing played), so no handle class. Every SoundEvent field on another class ends in `_sound`. | Ryan's approval. Ints need no new class name, like move lock ids. |
| 2026-09-27 | A SoundEvent wraps its files in Godot's `AudioStreamRandomizer` (no-repeat mode) for variations and jitter. Limits are our own: at most `max_instances` starts within any `min_interval` window (sliding, real time), extra starts dropped; a global SFX voice cap (32) where a higher priority steals the lowest, oldest sound. `max_polyphony` isn't used for limits. | Don't reinvent what Godot has. `max_polyphony` has no time window and cuts the oldest copy instead of dropping the new one. |
| 2026-09-27 | Principle wording: "`play()` is called in the same frame as its event". Godot adds its output latency (15 ms by default), and AudioStreamPlayer2D starts on its next physics tick. | What our code controls; the rest is Godot's. |
